# 质检报告模板

每次正式质检都按这个结构出，一条不省。

```markdown
# <项目名> 第 <集数> 集 质检报告

- 题材基线：<题材名> 清单V1
- 质检模式：正式验收 / 单点抽检（抽检时，本报告**不具备验收效力**）
- 版本：<集数·版本号>    质检时间：<日期>
- 质检人：<人/agent>      物料范围：脚本/分镜/图片/视频/成片

## 一、前置技能盘点
| 校验器 | 状态 | 说明 |
|---|---|---|
| sd-qc-engine | 就绪/缺失 | |
| ... | | |
> 强制校验器缺失：<列出>。已按替代方案执行，报告内标【人工复核·未自动校验】。建议安装：<校验器名>。

## 二、逐条明细
按清单顺序逐条写，每条必须写：结论（通过/不通过/未完成）、证据（哪一段哪一镜）、等级、执行校验器。

| 序 | 检查项 | 结论 | 证据（段/镜） | 等级 | 执行校验器 |
|---|---|---|---|---|---|
| 1 | | 通过 | 第2段·镜3 | — | frame-consistency-checker |
| 5 | | 不通过 | 第4段·镜1 | 🔴 | costume-consistency-checker |

## 三、逐段小结
每一段一行：段号 / 该段过的门禁条数 / 阻断数 / 一般数 / 是否可流转。

## 四、缺陷汇总
- 🔴 阻断：<条数与清单序>
- 🟡 一般：<条数与清单序>
- 🟢 优化：<条数与清单序>

## 五、结论
- 可验收 / 不可验收（原因）
- 需返工环节：<脚本/分镜/生图/视频/音频/字幕>

## 六、技能调用审计栏
| 应调用 | 已调用 | 未调用 | 未调用原因 |
|---|---|---|---|
| <清单内全部强制+补强> | | | |

## 七、缺口与人工复核位
| 条目 | 缺口 | 处理 | 复核人/状态 |
|---|---|---|---|
| 例：第9条 | 该条无对应机检校验器 | 替代校验：shot-continuity-inspector | 待人工确认 |

## 八、放行前置待办（自动生成，不可手填省略）
> 空表也写"无"。只要有一行不是"无"，本报告结论只能是**不可放行**。

① 准入凭证缺口
| 需要的凭证 | 状态 | 谁提供 | 补交后是否重跑 |
|---|---|---|---|

② 风险台账未销项
| 台账号 | 条目（清单序） | 等级 | 阶段 | 修复状态 | 销项签字 | 影响上线 |
|---|---|---|---|---|---|---|

③ 因缺校验器而未完成的条目
| 清单序 | 缺哪个校验器 | 替代方式 | 补齐后补跑范围 |
|---|---|---|---|

④ 进入下一关前置预告
| 下一阶段 | 必须带什么 | 谁签字 | 缺了卡在哪条 |
|---|---|---|---|

```

## 填写硬规则

- 「未完成」不等于「通过」：缺校验器又没人工复核的条目，只能写未完成。
- 证据必须落到段号和镜号，写"整体良好"视为无效报告。
- 审计栏的"未调用"必须写原因，不许留空。
- 报告落盘为文件交付，不允许只在对话里给结论。
